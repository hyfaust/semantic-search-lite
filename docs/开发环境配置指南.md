## 1. 系统要求

### 操作系统
- **Windows 10/11**（64-bit）— 主要开发平台
- Linux / macOS — 也可编译运行（需自行准备模型文件路径）

### 硬件
| 项目 | 最低要求 | 推荐配置 |
|------|---------|---------|
| CPU | 任意 64-bit | 支持 AVX2 的现代 CPU |
| 内存 | 4 GB | 8 GB+ |
| 磁盘 | 2 GB 可用空间 | 5 GB（含模型文件） |
| GPU | 不需要 | 不需要（ONNX CPU 推理足够） |

### 磁盘空间估算
```
Rust 工具链：        ~1.5 GB（含 rustup、toolchain、registry cache）
项目源码：          ~50 MB
ONNX 模型文件：     ~600 MB（model.onnx + model.onnx_data + tokenizer）
编译产物（debug）：  ~500 MB
编译产物（release）：~50 MB
─────────────────────────
总计：              ~2.7 GB（首次编译后）
```

## 2. 安装 Rust 工具链

### 2.1 安装 rustup

**Windows（推荐方式）：**

1. 下载 [rustup-init.exe](https://static.rust-lang.org/rustup/dist/x86_64-pc-windows-msvc/rustup-init.exe)
2. 双击运行，选择 **默认安装**（按 `1` 然后回车）
3. 安装完成后重启终端

**或使用 PowerShell：**

```powershell
# 下载并运行 rustup 安装程序
Invoke-WebRequest -Uri "https://win.rustup.rs/x86_64" -OutFile "$env:TEMP\rustup-init.exe"
& "$env:TEMP\rustup-init.exe" -y --default-toolchain stable
```

### 2.2 验证安装

打开 **新的** 终端（PowerShell 或 CMD），运行：

```bash
rustc --version
# 预期输出：rustc 1.82.0 (f6e511eec 2024-10-15) 或更高版本

cargo --version
# 预期输出：cargo 1.82.0 (8f40fc59f 2024-08-21) 或更高版本
```

### 2.3 确认 MSVC 构建工具

Rust 在 Windows 上默认使用 MSVC 链接器。检查是否已安装：

```bash
# 如果以下命令不报错，说明 MSVC 已就绪
rustup show
```

如果显示 `x86_64-pc-windows-msvc` 且没有错误，即可继续。

**如果缺少 MSVC 构建工具：**

1. 下载 [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)
2. 安装时勾选 **"使用 C++ 的桌面开发"** 工作负载
3. 安装完成后重启终端

### 2.4 配置镜像（可选，国内用户加速）

创建或编辑 `%USERPROFILE%\.cargo\config.toml`：

```toml
[source.crates-io]
replace-with = "ustc"

[source.ustc]
registry = "sparse+https://mirrors.ustc.edu.cn/crates.io-index/"

[net]
git-fetch-with-cli = true
```

## 3. 配置 ONNX Runtime

ONNX Runtime 由 Rust 的 `ort` crate **自动下载和链接**，无需手动安装。

### 3.1 ort crate 自动行为

`ort = "2.0.0-rc.10"` 会在首次编译时：

1. 自动下载 ONNX Runtime C++ 库（约 50-80 MB）
2. 缓存到 `%USERPROFILE%\.ort/` 目录
3. 静态链接到你的二进制文件

### 3.2 XNNPACK 执行提供者

Cargo.toml 中启用了 `features = ["xnnpack"]`：

```toml
ort = { version = "2.0.0-rc.10", features = ["xnnpack"] }
```

XNNPACK 是 Google 的高性能神经网络算子库，会自动启用。如果 XNNPACK 不可用，程序会 fallback 到 CPU 执行提供者。

### 3.3 验证 ONNX Runtime

首次编译项目时会自动下载。如果网络问题导致下载失败，可以手动设置：

```bash
# 设置 ONNX Runtime 库路径（可选，通常不需要）
set ORT_LIB_LOCATION=C:\path\to\onnxruntime

# 或使用环境变量跳过自动下载
set ORT_STRATEGY=system
```

## 4. 准备 AI 模型文件

### 4.1 模型文件清单

从 `EmbeddingGemma-300m/` 目录复制以下文件到项目的 `models/` 目录：

```
semantic-search-lite/models/
├── model.onnx              # ONNX 模型文件（~350 MB）
├── model.onnx_data         # 模型权重数据（~250 MB）
├── tokenizer.json          # HuggingFace tokenizer（~17 MB）
└── tokenizer_config.json   # tokenizer 配置（~1 KB）
```

### 4.2 获取模型

如果模型文件不在本地，可以通过以下方式获取：

**方式 A：从已有目录复制**

```powershell
# Windows PowerShell
$src = "F:\Users\code_data\vibe\embedding-models\EmbeddingGemma-300m"
$dst = "F:\Users\code_data\vibe\embedding-models\semantic-search-lite\models"
New-Item -ItemType Directory -Force -Path $dst
Copy-Item "$src\model.onnx" $dst
Copy-Item "$src\model.onnx_data" $dst
Copy-Item "$src\tokenizer.json" $dst
Copy-Item "$src\tokenizer_config.json" $dst
```

**方式 B：从 Hugging Face 下载**

```bash
# 需要安装 huggingface_hub CLI
pip install huggingface_hub

# 下载 EmbeddingGemma-300m ONNX 版本
huggingface-cli download google/EmbeddingGemma-300M --include "*.onnx" "*.json" --local-dir ./models
```

### 4.3 验证模型文件

```powershell
# 检查文件大小（约 600 MB 总计）
Get-ChildItem models/ | Format-Table Name, @{N="Size(MB)";E={[math]::Round($_.Length/1MB,1)}}
```

预期输出：
```
Name                  Size(MB)
----                  --------
model.onnx            350.0
model.onnx_data       250.0
tokenizer.json        17.0
tokenizer_config.json 0.0
```

## 5. 项目初始化

### 5.1 创建项目（从零开始）

```bash
# 创建新项目
cargo new semantic-search-lite
cd semantic-search-lite

# 或从现有模板克隆（如果有 git 仓库）
git clone <repo-url> semantic-search-lite
cd semantic-search-lite
```

### 5.2 添加依赖

编辑 `Cargo.toml`：

```toml
[package]
name = "semantic-search-lite"
version = "0.1.0"
edition = "2021"
rust-version = "1.80"

[dependencies]
# AI 推理
ort = { version = "2.0.0-rc.10", features = ["xnnpack"] }
tokenizers = { version = "0.22.2", default-features = false, features = ["onig"] }
ndarray = "0.16.1"

# 序列化
serde = { version = "1", features = ["derive"] }
serde_json = "1"
bincode = "2.0.1"
toml = "0.8"

# 并发
rayon = "1.11"
dashmap = "6.1"
parking_lot = "0.12"
lru = "0.16"

# CLI
clap = { version = "4", features = ["derive"] }
colored = "2"
tabled = "0.17"
indicatif = "0.17"

# 工具
anyhow = "1"
thiserror = "2"
tracing = "0.1"
tracing-subscriber = { version = "0.3", features = ["env-filter"] }
fuzzy-matcher = "0.3"
```

### 5.3 首次编译

```bash
# 首次编译会下载依赖和 ONNX Runtime，约需 3-10 分钟
cargo build

# 如果编译成功，你会看到：
#    Compiling ort v2.0.0-rc.10
#    Compiling semantic-search-lite v0.1.0
#     Finished `dev` profile [unoptimized + debuginfo] target(s) in 180.00s
```

**首次编译说明：**
- `ort` crate 会自动下载 ONNX Runtime 二进制文件（~80 MB）
- `tokenizers` 需要编译 C++ 依赖（oniguruma），可能需要 2-3 分钟
- 后续增量编译通常在 5-15 秒内完成

### 5.4 Release 编译

```bash
# Release 编译（优化后体积更小、速度更快）
cargo build --release

# 产物位置：
# target/release/semantic-search-lite.exe
```

### 5.5 目录结构验证

编译完成后，项目结构应如下：

```
semantic-search-lite/
├── Cargo.toml
├── Cargo.lock                # 自动生成
├── models/
│   ├── model.onnx
│   ├── model.onnx_data
│   ├── tokenizer.json
│   └── tokenizer_config.json
├── src/
│   ├── main.rs
│   ├── cli.rs
│   ├── core/
│   ├── search/

│   └── lib.rs
├── target/                   # 编译产物（gitignore）

```

### 7.1 编译验证

cargo build 2>&1 | tail -5

### 7.2 模型加载验证

创建测试文件 `src/main.rs` 进行最小化验证：

```rust
use ort::{Session, SessionOutputs};
use tokenizers::Tokenizer;
use ndarray::Array2;

fn main() -> anyhow::Result<()> {
    // 1. 加载 tokenizer
    let tokenizer = Tokenizer::from_file("models/tokenizer.json")
        .map_err(|e| anyhow::anyhow!("Tokenizer load failed: {}", e))?;
    println!("✅ Tokenizer loaded successfully");

    // 2. 加载 ONNX 模型
    let session = Session::builder()?
        .with_optimization_level(ort::session::builder::GraphOptimizationLevel::Level3)?
        .commit_from_file("models/model.onnx")?;
    println!("✅ ONNX model loaded successfully");
    println!("   Inputs: {:?}", session.inputs);
    println!("   Outputs: {:?}", session.outputs);

    // 3. 测试推理
    let encoding = tokenizer
        .encode("test query", true)
        .map_err(|e| anyhow::anyhow!("Tokenize failed: {}", e))?;
    let ids: Vec<i64> = encoding.get_ids().iter().map(|&x| x as i64).collect();
    let mask: Vec<i64> = encoding.get_attention_mask().iter().map(|&x| x as i64).collect();
    let len = ids.len();

    let ids_arr = Array2::from_shape_vec((1, len), ids)?;
    let mask_arr = Array2::from_shape_vec((1, len), mask)?;

    let inputs = ort::inputs!["input_ids" => ids_arr, "attention_mask" => mask_arr]?;
    let outputs = session.run(inputs)?;

    // 检查输出形状
    for (name, output) in outputs.iter() {
        if let Ok(tensor) = output.try_extract_tensor::<f32>() {
            let shape = tensor.shape();
            println!("   Output '{}': shape {:?}", name, shape);
        }
    }
    println!("✅ Inference completed successfully");

    Ok(())
}
```

运行验证：

```bash
cargo run
```

预期输出：

```
✅ Tokenizer loaded successfully
✅ ONNX model loaded successfully
   Inputs: [InputInfo { name: "input_ids", input_type: Tensor(Int64), ... }, ...]
   Outputs: [OutputInfo { name: "last_hidden_state", ... }, ...]
   Output 'last_hidden_state': shape [1, N, 768]
✅ Inference completed successfully
```

## 8. 常见问题

### Q1: 编译 `ort` 时下载 ONNX Runtime 失败

**症状：** `error: failed to download onnxruntime`

**解决方案：**

```bash
# 方案 A：设置代理
set HTTPS_PROXY=http://127.0.0.1:7890
cargo build

# 方案 B：手动下载 ONNX Runtime
# 从 https://github.com/microsoft/onnxruntime/releases 下载
# 解压后设置环境变量
set ORT_LIB_LOCATION=C:\path\to\onnxruntime-win-x64-1.20.0
set ORT_STRATEGY=system
cargo build
```

### Q2: `tokenizers` 编译失败（oniguruma 相关）

**症状：** `error: failed to run custom build command for 'onig_sys'`

**解决方案：**

```bash
# 方案 A：确保有 C 编译器（MSVC Build Tools）
rustup show  # 检查 toolchain

# 方案 B：使用预编译的 onig
set RUSTONIG_DEFAULT_FEATURES=1
cargo build

# 方案 C：移除 onig feature（退化正则性能）
# 在 Cargo.toml 中改为：
# tokenizers = { version = "0.22.2", default-features = false }
```

### Q3: `model.onnx` 加载时报内存不足

**症状：** `error: memory allocation failed`

**解决方案：**
- 确保系统有 4 GB+ 可用内存
- 尝试 release 编译（内存优化更好）：`cargo build --release`
- 检查是否有其他程序占用大量内存

### Q4: 推理速度很慢（>1 秒/次）

**可能原因：**
- Debug 模式运行 → 改用 `cargo run --release`
- CPU 不支持 AVX2 → 检查：`coreinfo` 或任务管理器 → 性能
- 首次推理有模型编译开销 → 第二次起会快很多

### Q5: 如何查看 ONNX Runtime 详细日志

```bash
# 设置 ONNX Runtime 日志级别
set ORT_LOG_LEVEL=VERBOSE
RUST_LOG=debug cargo run
```

### Q6: Windows Defender 影响编译速度

**症状：** 编译极慢（>10 分钟）

**解决方案：**
将项目目录和 Cargo 目录加入 Windows Defender 排除列表：

```powershell
# PowerShell（管理员）
Add-MpExclusion -Path "F:\Users\code_data\vibe\embedding-models\semantic-search-lite"
Add-MpExclusion -Path "$env:USERPROFILE\.cargo"
Add-MpExclusion -Path "$env:USERPROFILE\.rustup"
```
